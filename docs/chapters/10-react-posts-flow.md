# 10. React 게시글 화면 흐름

## 이번 챕터 목표

- 게시글 목록, 상세, 작성, 수정 화면을 연결한다.
- 같은 데이터를 여러 화면에서 다룰 때 중복을 줄인다.
- 사용자 행동 흐름 중심으로 화면을 설계한다.

## 먼저 이해할 개념

- Page flow: 사용자가 화면 사이를 이동하는 흐름
- Shared component: 여러 화면에서 재사용되는 컴포넌트
- Mutation side effect: 작성/수정/삭제 후 이동, 알림, 캐시 갱신
- Optimistic UI: 서버 응답 전 화면을 먼저 바꾸는 방식

## 직접 구현할 파일/기능

- 게시글 목록 페이지
- 게시글 상세 페이지
- 게시글 작성 페이지
- 게시글 수정 페이지
- 게시글 폼 컴포넌트
- 삭제 확인 UI

## 구현 전에 스스로 답할 질문

- 작성 폼과 수정 폼을 하나로 합칠 수 있을까?
- 목록 카드와 상세 화면은 어떤 정보를 공유할까?
- 삭제 후 사용자는 어디로 이동해야 할까?
- API 실패 시 작성 중인 내용은 유지되어야 할까?

## 단계별 실습 과제

1. 목록에서 상세로 이동한다.
2. 상세에서 수정으로 이동한다.
3. 작성과 수정이 같은 `PostForm`을 쓰도록 설계한다.
4. 작성 성공 후 상세 또는 목록으로 이동한다.
5. 수정 성공 후 상세로 돌아간다.
6. 삭제 성공 후 목록으로 이동한다.
7. 각 mutation 후 필요한 query를 invalidation한다.

## 힌트

- 힌트 1: `PostForm`은 submit 동작을 props로 받으면 작성/수정에 재사용하기 쉽다.
- 힌트 2: route params의 `postId`와 query key의 `postId`를 일관되게 맞춘다.
- 힌트 3: 삭제는 실수 방지를 위해 확인 단계를 둔다.

## 검증 명령과 성공 기준

```bash
pnpm --filter web build
pnpm --filter web lint
```

성공 기준:

- 목록에서 상세로 이동할 수 있다.
- 작성, 수정, 삭제 흐름이 끊기지 않는다.
- 작성/수정 폼 중복을 설명할 수 있다.
- mutation 이후 화면 데이터가 stale하게 남지 않는다.
