# 10. React Extendly 화면 흐름

## 이번 챕터 목표

- 익스텐션 목록, 상세, 등록, 수정 화면을 연결한다.
- 같은 데이터를 여러 화면에서 다룰 때 중복을 줄인다.
- 사용자 행동 흐름 중심으로 화면을 설계한다.
- MCP 자동수집, RAG 유사 검색, 댓글, 북마크를 화면 흐름에 배치한다.
- 메인 검색에서 카드 뷰와 목록(게시판 보드) 뷰를 오가며 같은 데이터를 다른 방식으로 탐색하게 한다.

## 먼저 이해할 개념

- Page flow: 사용자가 화면 사이를 이동하는 흐름
- Shared component: 여러 화면에서 재사용되는 컴포넌트
- Mutation side effect: 작성/수정/삭제 후 이동, 알림, 캐시 갱신
- Optimistic UI: 서버 응답 전 화면을 먼저 바꾸는 방식
- Draft state: 등록 폼에서 서버 저장 전 임시로 유지되는 값
- Progressive disclosure: 한 화면 안에서 단계별로 필요한 입력만 보여주는 방식

## 직접 구현할 파일/기능

- 익스텐션 목록/검색 페이지
- 익스텐션 상세 페이지
- 익스텐션 등록 페이지
- 익스텐션 수정 페이지
- 익스텐션 폼 컴포넌트
- MCP URL import box
- 자동 채움 preview
- 상세 metadata panel
- command palette와 view toggle
- 게시판 보드형 목록 item
- 댓글 영역
- 북마크 toggle
- 삭제 확인 UI

## 구현 전에 스스로 답할 질문

- 작성 폼과 수정 폼을 하나로 합칠 수 있을까?
- 목록 카드와 상세 화면은 어떤 정보를 공유할까?
- 삭제 후 사용자는 어디로 이동해야 할까?
- API 실패 시 작성 중인 내용은 유지되어야 할까?
- MCP 자동수집에 실패하면 등록 흐름은 멈춰야 할까, 수기 입력으로 계속 가야 할까?
- 상세 화면의 “비슷한 익스텐션 찾기”는 어떤 검색 상태로 이동해야 할까?
- 댓글 목록은 상세 페이지 안의 일부일까, 독립 query로 둘까?
- 목록 뷰에서 행 클릭, 내부 액션 버튼, 키보드 포커스는 어떻게 충돌 없이 설계할까?

## 단계별 실습 과제

1. 메인 목록에서 command palette 검색, 플랫폼 필터, 정렬 세그먼트를 연결한다.
2. `ViewToggle`로 카드 뷰와 목록 뷰를 전환하고 두 뷰 모두 상세 이동을 지원한다.
3. 목록 뷰 행에는 작성자, 댓글수, 등록일을 노출해 게시판 흐름을 증명한다.
4. 상세에서 원본 링크 열기, 북마크, 비슷한 익스텐션 찾기 CTA를 배치한다.
5. 상세 우측에 `ExtensionMetaPanel`을 두고 다운로드, 최신 버전, License, Compatibility, Permissions, 수집 시각, 새로고침을 표시한다.
6. 상세 하단에 댓글 입력과 댓글 목록을 연결한다.
7. 등록 페이지를 Step 1 원본 URL, Step 2 자동 채움 미리보기, Step 3 직접 수정, Step 4 제출로 구성한다.
8. 자동 채움 preview는 불러오기 전, 로딩, 성공, 실패 3-state 이상을 표현한다.
9. `UrlImportBox`에서 `POST /ai/fetch-metadata`를 호출해 draft 값을 채운다.
10. 작성과 수정이 같은 `ExtensionForm`을 쓰도록 설계한다.
11. 작성 성공 후 상세 또는 목록으로 이동한다.
12. 수정 성공 후 상세로 돌아간다.
13. 삭제 성공 후 목록으로 이동한다.
14. 각 mutation 후 필요한 query를 invalidation한다.

## 힌트

- 힌트 1: `ExtensionForm`은 submit 동작과 초기값을 props로 받으면 작성/수정에 재사용하기 쉽다.
- 힌트 2: route params의 `extensionId`와 query key의 `extensionId`를 일관되게 맞춘다.
- 힌트 3: 삭제는 실수 방지를 위해 확인 단계를 둔다.
- 힌트 4: 자동수집 preview는 성공 데이터와 사용자가 수정한 draft 데이터를 분리해서 생각한다.
- 힌트 5: 상세 metadata panel은 sticky로 둘 수 있지만 모바일에서는 본문 아래로 내려야 한다.
- 힌트 6: 메인 view toggle은 display class만 바꾸기보다 조건부 렌더링으로 두 표현 컴포넌트를 교체하면 구조가 단순하다.

## 검증 명령과 성공 기준

```bash
pnpm --filter web build
pnpm --filter web lint
```

성공 기준:

- 목록에서 상세로 이동할 수 있다.
- 카드 뷰와 목록 뷰 모두에서 상세로 이동할 수 있다.
- 작성, 수정, 삭제 흐름이 끊기지 않는다.
- 작성/수정 폼 중복을 설명할 수 있다.
- mutation 이후 화면 데이터가 stale하게 남지 않는다.
- MCP 자동 채움 성공/실패 흐름이 모두 화면에 있다.
- 상세 페이지에서 댓글, 태그, 신뢰 metadata와 MCP 패널의 권한/호환성/수집시각이 보인다.
- 메인 목록 뷰에서 작성자, 댓글수, 등록일이 보인다.
- 모바일에서 등록 stepper와 상세 metadata panel이 겹치지 않는다.
