# 09. React 폼과 인증 흐름: 로그인, 회원가입, 보호 화면

## 이번 챕터 목표

- 로그인과 회원가입 폼을 직접 만든다.
- 입력 상태, 검증 메시지, 제출 상태를 설계한다.
- 인증 token과 현재 사용자 상태를 관리한다.
- 등록, 북마크, 마이페이지처럼 인증이 필요한 Extendly 흐름을 준비한다.

## 먼저 이해할 개념

- Controlled input: React state가 input 값을 관리한다.
- Form validation: 제출 전 사용자 입력을 확인한다.
- Submit state: 제출 중, 성공, 실패 상태
- Auth state: 현재 로그인 여부와 사용자 정보
- Token storage: access token을 어디에 보관할지 결정하는 문제
- Protected action: 글 등록, 댓글 작성, 북마크처럼 로그인 후 가능한 행동

## 직접 구현할 파일/기능

- 회원가입 페이지
- 로그인 페이지
- auth API client
- 로그인 mutation
- 회원가입 mutation
- 현재 사용자 query
- 인증 상태 관리
- 로그아웃
- 인증이 필요한 CTA의 비로그인 처리

## 구현 전에 스스로 답할 질문

- input 값은 local state로 충분할까?
- 서버 validation 에러는 어느 위치에 보여줄까?
- 로그인 성공 후 어디로 이동할까?
- token을 저장하면 어떤 보안 문제가 생길 수 있을까?
- 비로그인 사용자가 `등록하기`, `북마크`, `댓글 작성`, `/me`를 누르면 어떤 안내가 자연스러울까?
- 로그인/회원가입 화면에도 공통 header를 둘까, 별도 auth shell로 집중도를 높일까?

## 단계별 실습 과제

1. 로그인 폼 필드를 정의한다.
2. 회원가입 폼 필드를 정의한다.
3. 제출 중 버튼 disabled 처리를 한다.
4. 클라이언트 검증 메시지를 만든다.
5. 서버 에러 메시지를 화면에 표시한다.
6. 로그인 성공 시 token 저장과 사용자 정보 갱신을 처리한다.
7. 로그아웃 흐름을 만든다.
8. `/extensions/new`와 `/me` 접근 시 인증 상태를 확인한다.
9. 댓글 작성과 북마크 버튼에서 비로그인 상태를 안내한다.
10. 로그인 후 원래 가려던 경로로 돌아갈지 정책을 정한다.

## 힌트

- 힌트 1: 처음에는 form library 없이 controlled input으로 흐름을 익히는 것이 좋다.
- 힌트 2: 제출 중 상태는 mutation의 `isPending`으로 표현할 수 있다.
- 힌트 3: 인증 상태는 “token”과 “현재 사용자 데이터”를 분리해서 생각한다.
- 힌트 4: 토큰 저장 방식은 과제 환경과 보안 설명을 함께 남긴다. 완벽한 방식보다 trade-off를 설명하는 것이 중요하다.
- 힌트 5: 비밀번호 오류, 중복 이메일, 네트워크 오류는 서로 다른 문구로 구분한다.

## 검증 명령과 성공 기준

```bash
pnpm --filter web build
pnpm --filter web lint
```

성공 기준:

- 잘못된 입력은 제출 전에 안내된다.
- 서버 에러가 사용자에게 보인다.
- 로그인 후 인증이 필요한 화면으로 이동할 수 있다.
- 새로고침 이후 인증 상태 처리 방식을 설명할 수 있다.
- 로그아웃 후 보호된 행동이 다시 막힌다.
- 비로그인 사용자가 등록/댓글/북마크를 시도했을 때 다음 행동이 분명하다.
