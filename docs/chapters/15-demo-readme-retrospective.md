# 15. 데모, README, 회고

## 이번 챕터 목표

- 제출물로서 프로젝트를 정리한다.
- README가 평가자에게 충분한 정보를 주도록 만든다.
- 데모와 회고를 통해 구현 경험을 설명한다.

## 먼저 이해할 개념

- Architecture documentation: 시스템 구조를 설명하는 문서
- Demo scenario: 기능을 보여주는 실행 흐름
- Retrospective: 잘한 점, 한계, 개선점을 정리하는 글
- Evidence: 스크린샷, API 응답, 구조도 같은 증거

## 직접 구현할 파일/기능

- 루트 `README.md` 최종 정리
- 아키텍처 다이어그램
- RAG/MCP/Agent 상세 설명
- 데모 스크린샷
- 회고와 개선 아이디어

## 구현 전에 스스로 답할 질문

- 평가자가 처음 볼 때 이 프로젝트가 무엇인지 30초 안에 이해할 수 있을까?
- AI 기능 3가지는 각각 어떤 문제를 해결하는가?
- 데모는 어떤 순서로 보여주는 것이 자연스러울까?
- 한계점을 솔직하게 쓰되, 개선 방향도 제시하고 있는가?

## 단계별 실습 과제

1. 프로젝트 개요를 5문장 이내로 쓴다.
2. 주요 기능 목록을 사용자 기능과 AI 기능으로 나눈다.
3. 전체 아키텍처를 그린다.
4. RAG 기능의 데이터 흐름을 설명한다.
5. MCP 기능의 tool과 외부 서비스 연동을 설명한다.
6. Agent 기능의 loop와 guard를 설명한다.
7. 데모 스크린샷을 추가한다.
8. 회고, 한계점, 개선 아이디어를 쓴다.

## 힌트

- 힌트 1: README는 구현 순서가 아니라 결과물을 이해하는 순서로 쓴다.
- 힌트 2: AI 기능은 “무엇을 썼다”보다 “왜 필요한가”를 먼저 설명한다.
- 힌트 3: 회고는 추상적인 감상보다 실제 문제와 결정이 들어가야 좋다.

## 검증 명령과 성공 기준

```bash
pnpm build
```

성공 기준:

- README가 제출물 요구사항을 모두 포함한다.
- 스크린샷이 1개 이상 있다.
- RAG, MCP, Agent 설명이 각각 분리되어 있다.
- 한계점과 개선 아이디어가 구체적이다.
